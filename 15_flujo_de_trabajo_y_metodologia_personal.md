# Guía — Flujo de trabajo y metodología personal

## Objetivo

Construir un flujo de trabajo sostenible para proyectos personales y aprendizaje autodidacta.

---

# Problema frecuente

Muchos desarrolladores autodidactas:
- intentan hacer demasiado
- cambian constantemente de tarea
- abandonan proyectos

---

# Regla principal

Trabajar en:
- pasos pequeños
- objetivos concretos
- progreso constante

---

# Método recomendado

```text
1. Elegir tarea
2. Programar
3. Testear
4. Commit
5. Descansar
```

---

# Una tarea por sesión

❌ Malo:

```text
Backend + UI + DB + deploy
```

✅ Mejor:

```text
Corregir validación login
```

---

# TODO.md

Usarlo para:
- ideas
- bugs
- mejoras
- próximos pasos

---

# Commits como checkpoints

Cada commit es:
- un punto seguro
- un registro
- una versión funcional

---

# Evitar perfeccionismo

Muchos bloqueos vienen de:

```text
"todavía no está perfecto"
```

La prioridad debe ser:
- terminar
- iterar
- mejorar progresivamente

---

# Retomar proyectos

Antes de cerrar sesión:

```text
- actualizar TODO
- dejar comentarios claros
- hacer commit
```

Esto facilita muchísimo volver después.

---

# Sesiones pequeñas

Incluso:
30 minutos diarios

superan:
- caos
- agotamiento
- intensidad inconsistente

---

# Filosofía importante

La constancia supera a la motivación.

---

# Consejo final

No necesitas:
- saber todo
- usar todas las tecnologías
- hacer proyectos enormes

Necesitas:
- consistencia
- práctica real
- proyectos terminados
- flujo sostenible
